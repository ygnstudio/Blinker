# Blinker 从零重构规划

状态：待用户确认。日期：2026 年 10 月 8 日。

本方案把 Blinker 作为一个新产品重新设计。旧代码、模块边界、窗口结构、配置模型和功能集合都不构成必须保留的基础。旧工程只提供实际使用场景、已知问题和迁移输入；新工程不以复用旧 Controller、View 或 Store 为目标。

推荐定位为原生 macOS 窗口工具：通过标题栏、Dock 和键盘，更直接地操作和寻找窗口。系统状态中心及通用工具箱作为另一种范围选择列出，不能在用户尚未确认时擅自删除。性能、可靠性、原生交互和数据迁移共同构成完成标准。

本轮交付规划及交互原型，不创建新应用工程，不更改现有实现，不安装或发布重构版本。只有用户确认范围和方案后，才进入实施。

## 需要确认的产品范围

| 决策 | 推荐方案 A 窗口工具 | 备选方案 B 完整工具箱 |
| --- | --- | --- |
| 产品目标 | 标题栏、Dock、键盘的窗口操作 | 窗口操作加系统状态、设备控制与屏幕效果 |
| 新界面 | 窗口行为主窗口、精简设置、原生菜单、专用浮层 | 相同窗口核心，另设工具窗口及模块配置，不将所有功能塞进规则编辑器 |
| 新实现 | 核心四层全部重写 | 核心四层及外围服务全部重写，必要时增加 XPC helper |
| 权限 | 辅助功能；可选屏幕录制；输入能力按实际 API 检测 | 另有定位、蓝牙、自动化、输入监控、设备能力与特权服务 |
| 常驻成本 | 无关系统采样服务不进入进程生命周期 | 每个模块必须显式启用、按需运行并有独立资源预算 |
| 时间估算 | 约 35–51 人日，加兼容性缓冲 | 约 57–87 人日，加兼容性缓冲 |
| 主要代价 | 新版不提供一部分旧工具，需要明确接受功能收敛 | 开发与验收面明显扩大，窗口主线交付更晚 |

推荐 A，因为它减少了后台工作、权限数量和产品认知负担。B 同样是从零重建，不是保留旧基础。原型展示 A；选择 B 后，先补齐工具窗口、状态与设备操作原型，再开始相应实现。选择 A 不意味着现在删除旧功能或旧数据。

B 默认包含下表中现有的全部功能目的，包括边缘贴靠、复杂触发和外围工具；不要求像素一致或延续每个装饰参数。外观选项若收敛为系统预设，迁移报告必须列出对应关系与差异。任何功能删减都需在规格冻结时逐项确认，不能以“原生化”为由隐性移除。

| 悬停放大与额外按钮 | 改为依附目标窗口的原生操作浮条，重做防误触 | 相同，复杂自定义外观收敛为系统尺寸与语义色 |

| 窗口缩略图与标签页 | 缩略图可选；标签页按应用实际能力展示，不承诺全部应用支持 | 相同 |
| 半屏、四分屏、三分屏、居中、最大化、全屏、跨屏、还原 | 统一动作体系，通过规则、菜单及快捷键调用 | 相同 |
| 自有边缘拖动贴靠 | 建议移除，避免与系统平铺竞争；保留显式布局动作 | 纳入重建，设置唯一开关，验证与系统平铺同时启用的冲突策略 |
| Dock 再次点击收起与恢复 | 可选，默认关闭，保留同一次操作的恢复集合 | 相同 |
| 显示桌面与恢复 | 保留；只恢复本次收起的窗口 | 相同 |
| 全局快捷键 | 首发核心；统一录制、冲突检查、清除、恢复 | 相同 |
| 工作区保存与恢复 | 后置；首发不出现空入口 | 独立实验能力，明确只匹配已有窗口，不恢复文稿 |
| 跨 Space 恢复 | 首发不使用私有 API；未来单独评估 | capability adapter 隔离，默认关闭，失效不阻塞公开能力 |
| 菜单栏与 Dock 状态图标 | 菜单栏采用简单身份与运行状态；移除组合硬件监控图形 | 重做图标模型、显示位置、交互和模块可见性，禁止与规则状态混存 |
| 电池、电源、网络、IP、VPN、蓝牙、存储、性能 | 不进入新核心 | 各自 provider，单项慢读取不阻塞其他模块；未知值不得显示为 0 |
| 输入输出音频与设备切换 | 不进入新核心 | CoreAudio 状态与命令分离，外部变化同步，失败保留真实旧状态 |
| 低电量模式与保持唤醒 | 不进入新核心 | 用户显式执行；helper 身份校验、限权、超时、错误和卸载完整覆盖 |
| 锁屏、睡眠、屏保、显示器模式、Finder 操作 | 不进入新核心 | 系统工具分组，配置不触发执行；不可确认成功时显示请求状态 |
| 清空回收站 | 不进入新核心 | 删除前明确确认；权限拒绝可恢复；计数权限与清空权限分别说明 |
| 显示器清洁与键盘清洁 | 不进入新核心，可另立产品 | 独立 session；始终可退出；失焦、锁屏、睡眠、撤权后不能残留输入锁定 |
| 快捷指令槽位 | 不进入新核心 | 执行中的取消、超时、失败及名称变化有确定处理 |
| Duo 开合盖效果 | 不进入新核心，可另立产品 | 传感器与抓图单独管理；默认关闭；不干预系统合盖睡眠 |

首发不增加账号、云同步、插件市场、AI 功能或自动更新系统。它们不属于本次窗口体验与原生重构的必要条件。

## 新的信息架构

### 窗口行为主窗口

主窗口编辑用户定义的规则。左侧只有“默认行为”与应用例外；右侧只有所选范围的编辑器。工具栏放添加、兼容性测试与更多操作，不展示硬件仪表盘。

默认行为初始全部使用系统动作。应用例外逐项选择“继承默认”“保留系统行为”或具体动作；这些选项具有不同含义。高级区域容纳修饰键、长按和窗口例外。关闭应用自定义后恢复继承，数据仍保留；显式选择“保留系统行为”则覆盖全局自定义。

搜索只筛选列表，不修改规则，也不自动改变用户正在编辑的目标。选中项暂时被过滤时保留编辑上下文并给出说明；清空搜索返回原选择。重复添加同一 Bundle ID 打开已有规则，不覆盖内容。

### 系统设置窗口

设置管理运行偏好，不承担规则内容编辑。推荐五项：

| 页面 | 内容 |
| --- | --- |
| 通用 | 启动、外观、语言、暂停与运行状态 |
| 标题栏与布局 | 悬停尺寸与延迟、点击保护、Dock 点击策略、布局边界 |
| 预览与切换 | Option–Tab、Dock 悬停、窗口范围、标签页与缩略图 |
| 快捷键 | 动作录制、冲突、注册失败、清除和恢复 |
| 权限与诊断 | 能力可用性、权限状态、目标应用兼容性、可导出的错误摘要 |

采用独立窗口是基于“编辑规则”和“调整软件偏好”的任务区别重新得出的选择，不复用现有窗口控制器或导航状态。正式实现优先 `Settings` scene；需要 AppKit bridge 时保持系统菜单、快捷键、窗口复用及响应链语义。

### 日常运行界面

菜单栏使用简短 `NSMenu`，提供运行状态、窗口行为、设置、显示桌面、暂停与恢复、帮助、退出。没有常驻数据仪表盘。

悬停浮条依附原窗口的红绿灯区域，显示有文字及辅助功能标签的系统按钮。它不改画一套巨大的仿真红绿灯，不遮住拖动标题栏的主要区域，不抢走目标应用焦点。

Dock 预览与键盘切换共用窗口目录、选择模型和动作服务，分别使用适合指针与键盘的承载。缩略图是渐进补充内容，选择和标题先可用。调节预览尺寸只改变图片、列数与间距，文字和命中区域不整体缩小。

### 原型画面与审阅路径

`blinker-prototype.html` 是可交互的中保真方案，包含：

1. 默认行为与逐应用例外，可修改、恢复继承、撤销。
2. 添加应用 sheet，可搜索、取消和识别重复应用。
3. 悬停浮条的保护中与可点击状态。
4. 五类设置，重点展示标题栏、切换与快捷键。
5. 权限页，以及仅缺录屏时的切换降级。
6. 原生菜单的信息结构。
7. 窗口切换与无缩略图状态。

原型中的数据、动作结果与窗口画面均为示例，不读取或更改系统。顶部导航用于切换评审画面，不是正式软件的导航。原型不精确复刻 Liquid Glass，不等同于 SwiftUI／AppKit 实机渲染；迁移报告、冲突导入、全部错误状态在实施前的规格阶段继续细化。

建议按“默认行为 → Safari 例外 → 修改缩放动作 → 访达 → Safari → 撤销 → 添加应用 → 设置 → 权限 → 窗口切换降级”审阅，重点确认是否理解继承、配置与执行的区别。

## 从零建立的架构

### 模块与依赖

推荐 A 使用四个生产 target，B 按需增加两个特权服务 target。模块数量服务于依赖和测试边界，不为拆分而拆分。

| 模块 | 职责 | 不允许承担 |
| --- | --- | --- |
| BlinkerDomain | 规则决策、触发、命令、布局算法、配置验证，纯 Swift 值类型 | AppKit、AX、截图和持久化 I/O |
| BlinkerPlatform | EventTap、AX、ScreenCaptureKit、权限、系统与显示器适配 | 产品导航、SwiftUI 状态和规则编辑 |
| BlinkerRuntime | 会话、命令队列、窗口目录、预算、配置仓库、运行状态与诊断 | 创建窗口、绘制页面、按 View 生命周期执行系统命令 |
| BlinkerApp | AppKit 生命周期与场景、SwiftUI 界面、菜单、浮层与意图派发 | 同步扫描全部窗口、直接操作 AX、复制服务状态 |
| BlinkerHelperProtocol | B 的版本化最小 XPC 协议 | 任意命令执行接口 |
| BlinkerPrivilegedHelper | B 的经调用者验证、限权、限时操作 | 解析 UI 偏好、接受任意路径和参数 |

依赖方向为 `App → Runtime → Domain / Platform`；Platform 只借用必要的 Domain 值类型。新代码不能反向引用旧 BlinkerCore 或旧 App target。旧数据转换器在边界读取历史格式，不让旧 key 与兼容分支进入新领域模型。

### 状态所有权

`@MainActor AppSession` 唯一拥有应用运行状态，`WindowCoordinator` 唯一拥有窗口与浮层。UI 使用 Observation 展示状态，不成为服务的 owner。配置 repository actor 唯一写磁盘；输入执行器拥有事件与按压状态；AX 执行器拥有 AX 句柄；图像服务拥有抓图 session 与图片预算。

用户期望开关与实际运行状态必须分开。例如“用户已开启 Dock 预览”与“因辅助功能被撤回而暂停”同时成立，不能把权限失败写回用户开关。权限、硬件能力、命令结果各有独立状态。

### 输入与动作链路

`原始输入 → 同步判定 → 透传或消费 → 不可变命令 → 目标复核 → 执行 → 结果反馈`

同步回调只读取不可变规则及权限快照，做坐标预筛、按压状态转换及必要的有预算命中判定。禁止等待 MainActor、磁盘、网络、截图或完整窗口目录。无关事件立即透传；超预算必须选择预先定义的安全失败行为。

命令包含 request ID、输入来源、目标令牌、动作、规则版本和有效期。目标令牌由窗口服务签发，关联进程启动身份、运行会话和窗口代次；几何、标题及缩略图只用于辅助定位。目标无法确认时不执行，也不回退到另一个焦点窗口。

按压状态机明确区分空闲、按下、等待、触发、取消及释放。取消、拖离、暂停、目标消失、撤权和新一次按下都能使旧意图失效。已消费 mouse-down 的后续释放必须配对处理，不能在链路中途简单“全部透传”造成孤立事件。

AX IPC 使用有界执行器，单一目标串行；布局意图可合并，关闭或退出不能自动重试。停止流程为禁止新事件、失效在途意图、停止系统回调、等待安全退出、释放资源，不能以打印超时日志代替生命周期完成。

### 新规则模型

`ApplicationRule` 通过 `Trigger → ActionBinding` 表达规则。Trigger 包含按钮、修饰键、手势；Binding 明确区分 `inherit`、`systemDefault`、`perform(action)`、`suppress`、`followPrimaryClick`，并验证每个 trigger 可用的 binding。

| 选项 | 含义 |
| --- | --- |
| 继承默认 | 只用于应用例外，解析全局对应触发项 |
| 保留系统行为 | 不执行 Blinker 自定义动作；不能再解析为继承 |
| 具体动作 | 形成经过能力及目标校验的命令 |
| 不执行动作 | 显式消费此自定义触发；只在高级模式提供，不能与未配置混淆 |
| 跟随普通单击 | 适用于长按等允许此语义的触发，界面明确显示；避免用空值表示 |

规则初始不引入退出、关闭全部等破坏性动作。危险动作在选择时解释作用范围；不能对用户明确配置的动作每次都弹无意义确认。布局与窗口命令、显示桌面与暂停等应用命令分型建模，避免所有行为塞入一个大 enum。

## 性能规划与测量

以下为规划目标，尚未实测，不是已经实现的性能保证。实施先测空应用与典型使用基线，再冻结验收阈值。无法达到时提交数据、瓶颈及调整建议，不能悄悄放宽指标。

| 场景 | 初始目标 | 测量方式 |
| --- | --- | --- |
| 核心运行，静止 60 秒，无浮层 | 平均 CPU ≤ 0.5% 单核；目标常驻内存 ≤ 100 MiB；无抓屏会话 | Release 构建，预热后重复 5 次，Instruments 与进程 footprint |
| 无关输入 | EventTap 回调 p95 ≤ 2 ms，p99 ≤ 5 ms | signpost，至少 1000 次受控输入 |
| 命中输入 | 热路径 p95 ≤ 8 ms；探索约 20 ms 总判定预算 | 回调耗时与超预算比例同时报告；AX 可能阻塞，必须以实测约束策略 |
| 窗口切换 | 热目录首屏 ≤ 100 ms；20 窗口冷首屏 ≤ 250 ms | 从快捷键开始到标题可选择，不以全部截图完成作为首屏 |
| 缩略图 | 第一项优先；初始图片缓存预算 32 MiB，可见图片另计并设总上限 | 包含实际解码内存、可见强引用与抓图队列，不能只统计缓存字典 |
| 界面响应 | 常规输入无超过 100 ms 的主线程停顿；60 Hz 下帧工作遵守约 16.7 ms 预算 | Hangs、Time Profiler、动画卡顿录制；120 Hz 专项检查 |
| 耐久 | 100 次切换／浮层开关后资源回落，无持续内存、线程、会话增长 | 起始、峰值、关闭后稳定值；Leaks 与 Allocations |
| 电源与睡眠 | 无界面且无需求不截图；睡眠停止采样；唤醒只恢复用户已启用能力 | 会话数量、timer、唤醒次数与 Energy Log |

图片管线的总峰值包括缓存、可见引用、正在解码及系统捕获队列。实施阶段需测量并冻结整体上限与压力降级阈值；没有整体预算记录，窗口切换工作包不得通过验收。32 MiB 仅是初始缓存预算，不能作为全部图片内存的承诺。

基准条件记录芯片、RAM、OS build、显示器数量／缩放、20 个窗口的应用构成、配置规模及权限。至少补测 100 个窗口、1000 条规则、无响应 AX 应用、低电量、多屏断连。旧版测量只作对照，不作为新架构设计限制。

优化顺序：先减少不必要服务，再缩短同步热路径，接着优化窗口发现和失效，再调整图片与 UI 更新。具体策略包括不可变输入快照、有界队列、窗口目录渐进更新、可取消发布资格、可见项优先抓图、全局扫描 deadline 和内存压力清理。

B 的状态 provider 独立发布数值、读取时间、过期与错误；事件优先，轮询仅补缺。面板关闭后仅采样图标确实需要的数据。低电量与睡眠改变采样预算，不生成新 worker 替代永久阻塞的旧调用。Duo 独立设分辨率、帧率与帧队列上限，开启时单独测量，不能用 A 的空闲 CPU 指标掩盖特效负载。

## 权限与兼容性

核心仅在需要时申请权限。辅助功能拒绝或撤回时暂停相应窗口操作，保持系统输入正常；仅缺屏幕录制时，允许已有辅助功能支持的图标与标题切换。请求权限不等于已获得权限，返回应用后重新检测。[Apple AX 授权接口](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions)

EventTap 的创建失败、超时禁用、用户输入禁用、睡眠与退出分别处理，不做无限重启循环。仅监听的入口与主动过滤的入口使用正确系统选项。[Apple EventTap](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate(tap:place:options:eventsofinterest:callback:userinfo:))

缩略图按需使用 ScreenCaptureKit；关闭面板或会话失效后不得发布旧图。队列深度显式设置并计入预算，不依赖可能变化的 SDK 默认值。[Apple 屏幕捕获](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)、[帧队列说明](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/queuedepth)

首发核心使用公开系统 API。某个应用的自绘按钮、标签页或受限窗口不能识别时明确不支持，不能猜测并操作其他对象。B 的 Space、传感器、蓝牙补充信息及未文档化系统细节通过隔离适配器提供，所有失败能退回公开能力或关闭该可选功能。

B 的 helper 验证连接方 audit token 与代码签名要求；固定允许命令、参数及目标，拒绝任意执行；采用协议版本、单操作串行、deadline、一次性结果与错误分类。Developer ID 与开发签名分别定义验证策略，不能用任意本地进程均可调用的方式换取方便。

## 数据迁移与回滚

新配置写入独立版本化 `ConfigurationEnvelope`，包含 schemaVersion、revision、默认规则、应用例外、快捷键及运行偏好。repository actor 先验证临时文件再原子替换，并保留最近有效备份。暂停状态、窗口目录、截图、实时日志不进入用户配置。

旧数据采用一次性导入，不自动覆盖：读取旧快照 → 解析与校验 → 展示可迁移／需处理／未纳入新版项目 → 用户确认 → 新库原子保存 → 提供迁移报告与撤销。原快照和旧配置始终保留。

必须区分旧缺省、显式无动作、未设置快捷键与主动清除；不能把它们都映射到“继承默认”。无法等价迁移的规则保持未启用并解释原因，不能推测用户意图。A 未纳入的状态、特效与工具配置进入归档，不偷偷删除。B 对每个模块建立独立迁移 fixture。

开发预览使用独立 Bundle ID 与配置目录，避免污染当前版本。新旧版本不能同时安装同类输入监听：测试与切换流程必须提示只运行一个窗口增强引擎。TCC 授权由系统管理，不能复制、绕过或自动重置。

回滚为退出新版、恢复旧版及其原配置，结束新服务和浮层；B 还需明确 helper 的版本管理与卸载。最终 Bundle ID、签名和发行渠道在发布前确定，不能把替换安装视为无差异操作。

## 发布标准与确认清单

完成意味着：新架构无旧模块依赖、批准范围全部实现、26／27 分别验收、性能预算有原始记录、真实输入无已知阻断、迁移可解释且可回滚、原生 UI 和辅助功能通过。核心体验不应依靠私有 API，功能关闭后相关资源应确实释放。

待用户确认四项：

1. 范围选择 A 窗口工具，或 B 全部能力重新构建；也可明确点名 A 中需要保留为新版可选模块的功能。
2. 是否接受“默认行为加应用例外”、精简设置、原生操作浮条与简短菜单的方向。
3. 新旧配置隔离、逐项导入、无法等价迁移时不自动启用的策略。
4. 最低 macOS 26.0、27 实机作为发布门槛；Intel 是否继续作为正式发行目标。

用户确认前，工作停留在这份规划和原型；不会据此启动代码重构。
