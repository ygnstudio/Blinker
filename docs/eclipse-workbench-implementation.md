## 3. 已有模型与新增能力的边界

[AppRule](../Sources/BlinkerCore/Models/AppRule.swift) 已增加显式 `inheritedSlots`；[RuleConfiguration](../Sources/BlinkerCore/Models/RuleConfiguration.swift) 同时保存 `GlobalButtonRules` 与应用例外。旧记录缺少继承字段时仍按空集合解码，原 nil 保留系统行为。应用工作区中的新规则使用 `AppRule.inheritingDefaults`，未单独配置的应用也直接采用全局默认；这不改变兼容旧数据的普通初始化器语义。

[ButtonAction](../Sources/BlinkerCore/Models/ButtonAction.swift) 继续区分显式 none 与未配置，保留全部布局动作；普通点击、右键、Option、Fn、长按按既有触发语义处理。按钮规则停用会抑制此应用的全局默认，配置仍保留；悬停开关独立，重置按钮规则保留原悬停值。窗口与悬停已有独立预览，悬停页不再出现按钮继承操作。

| 原型项目 | 实际边界 | 本轮呈现要求 |
| --- | --- | --- |
| 默认行为 / 沿用默认 | 已有全局默认与显式绑定，解析、UI、存储和撤销接入同一配置快照 | 旧 nil 仍为系统；新应用继承；显式系统覆盖默认，来源与示意同步更新 |

| Command / Option 映射 | 窗口动作快捷键已有，通用应用键位映射不是同一能力 | 保留新增计划，不画出可成功保存并生效的假映射 |

| Trio 电量 / 网络 / 音量 | 当前产品已有真实组合图标和状态服务 | 接真实快照及未知状态；原型 88%、Wi-Fi、65% 不进入正式状态页 |
| 磁盘清理 | 当前物理屏幕 / 键盘清洁、容量读数不是磁盘分析清理 | 分开登记入口和阶段，不能因名字相近声称已覆盖 |

真实规则编辑的“撤销”只撤销配置事务。关窗、退出、系统请求、废纸篓及设备切换不因此变成可无条件撤销。

当前导出使用 v2 JSON 完整保存默认与应用规则，不会静默丢弃继承依赖；无应用例外时也可导出默认值。v2 导入合并应用规则并采用文件默认，v1 不带默认的导入保留当前默认，两者都作为单一完整配置事务进入撤销历史。文件大小与数量限制继续保留。较新持久化版本进入只读，阻止修改及不完整导入 / 导出，保留原数据；应用工作区显示“配置预览不可用”，不从无法读取的数据推断默认状态。
